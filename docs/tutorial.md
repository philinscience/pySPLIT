# Tutorial: SPLIT on real 10x Xenium breast cancer data

This walks the complete pySPLIT workflow on a public Xenium sample, mirroring
the original SPLIT [Xenium vignette](https://github.com/bdsc-tds/SPLIT/blob/main/vignettes/Run_RCTD_and_SPLIT_on_Xenium.Rmd)
but entirely in Python.

There are two runnable versions:

* **[`examples/tutorial_xenium_breast_cancer.ipynb`](../examples/tutorial_xenium_breast_cancer.ipynb)**
  — the same walkthrough with figures, committed with its outputs so it renders
  on GitHub as-is. Start here if you want to *see* the result.
* **[`examples/tutorial_xenium_breast_cancer.py`](../examples/tutorial_xenium_breast_cancer.py)**
  — the headless script, for batch runs. The notebook imports its helpers, so
  the two stay in step.

```bash
pip install "pysplit-st[all]" rctd-py scanpy openpyxl

jupyter lab examples/tutorial_xenium_breast_cancer.ipynb   # with plots
python examples/tutorial_xenium_breast_cancer.py           # headless
```

This document is the narrative reference; the notebook is the same material with
charts attached. The notebook is committed with its outputs, and its source
cells are generated by
[`examples/_build_notebook.py`](../examples/_build_notebook.py) so prose and
chart edits show up as a readable diff rather than as notebook JSON.

Every stage caches to `--outdir` (default `./pysplit_tutorial`), so re-running
is cheap and an interrupted run resumes.

Measured on 18 CPU cores, no GPU: ~40 s for RCTD on the cropped region, a few
minutes for the whole script including downloads. The `--full-section` run is
roughly 20x the cells.

## The data

> Janesick, A., Shelansky, R., Gottscho, A.D. et al. *High resolution mapping of
> the tumor microenvironment using integrated single-cell, spatial and in situ
> analysis.* **Nature Communications** 14, 8353 (2023).

| | |
|---|---|
| **Spatial** | Xenium FFPE Human Breast Cancer, Rep 1 — 167,780 cells × 313 genes |
| **Reference** | Chromium FFPE Human Breast Cancer — 26,031 annotated cells × 18,082 genes, 17 cell types |

Both download automatically (~200 MB total). The script crops to `x > 6000,
y > 4000` — **7,804 cells** — so the tutorial runs in minutes; pass
`--full-section` for all 167k cells.

Cropping, not random subsampling, matters here: SPLIT's spatial mode reasons
about physical neighbourhoods, and subsampling would tear them apart.

## Step 1 — a reference worth deconvolving against

```python
reference = sc.read_10x_h5("chromium.h5")
reference.obs["cell_type"] = annotation["Annotation"].reindex(reference.obs_names)
keep = reference.obs["cell_type"].notna() & ~reference.obs["cell_type"].str.contains("Hybrid")
reference = reference[keep].copy()
```

Dropping the study's own `Hybrid` (doublet) calls is not cosmetic. A reference
containing doublets teaches the deconvolution that mixed profiles are
legitimate cell types — exactly the signal SPLIT exists to remove.

### Higher-level classes

```python
class_df = dict(CELL_TYPE_TO_CLASS)      # 17 cell types -> 7 classes
```

Note the format: `rctd-py` wants a plain `{cell_type: class}` **dict**, whereas
the R package takes a `data.frame`. Handing `rctd-py` a DataFrame fails with
`class_df is missing entries for cell types: [...]` listing *every* type, because
the membership test hits the DataFrame's columns. pySPLIT itself accepts a dict,
Series or DataFrame.

Strongly recommended. Grouping `CD4+_T_Cells` and `CD8+_T_Cells` under `T cell`,
the four tumour populations under `Epithelial`, and so on, lets RCTD stop
agonising over distinctions a 313-gene panel cannot resolve. It makes the
deconvolution more robust and sharply reduces rejected cells — which SPLIT would
otherwise discard. It also unlocks the `*_class` neighbourhood metrics that
SPLIT-shift depends on.

## Step 2 — deconvolution (RCTD, doublet mode)

```python
import rctd

rctd_reference = rctd.Reference(reference, cell_type_col="cell_type", min_UMI=10, cell_min=25)
config = rctd.RCTDConfig(UMI_min=10, counts_MIN=10, UMI_min_sigma=100, class_df=class_df)
result = rctd.run_rctd(xenium, rctd_reference, mode="doublet", config=config)
```

**Doublet mode is required.** SPLIT's whole premise is a primary and a secondary
cell type per cell; full mode gives no such decomposition.

### Two `rctd-py` gotchas worth knowing

**1. `compile=True` is the default, and it is a trap on CPU.** `rctd-py` hands
its solver to `torch.compile`, which pays for itself on a GPU but costs many
minutes of one-time torchinductor compilation on CPU — long enough to look like
a hang, with the process sitting in `futex_wait` and no output. The tutorial
switches it off when no GPU is present:

```python
import torch
on_gpu = torch.cuda.is_available()
config = rctd.RCTDConfig(..., compile=on_gpu)
```

**2. It auto-downloads a ~400 MB Q-matrix cache** to `~/.cache/rctd` on first
use, via `urllib`. On clusters where Python's SSL trust store is incomplete
this fails with `CERTIFICATE_VERIFY_FAILED` even though `curl` and `pip` work
fine. Fetch it by hand:

```bash
mkdir -p ~/.cache/rctd && curl -L -o ~/.cache/rctd/q_matrices.npz \
  https://github.com/p-gueguen/rctd-py/releases/download/v0.1.1/q_matrices.npz
```

### Handing it to pySPLIT

```python
rctd_result = pysplit.from_rctd_py(
    result,
    reference=profiles,                  # cell types x genes, restricted to the panel
    cell_ids=list(xenium.obs_names),
    class_df=class_df,
    coords=xenium.obs[["x", "y"]],
)
```

`from_rctd_py` also runs `run_post_process_rctd` for you. That step is **not
optional**: RCTD reports a `second_type` even for cells where one cell type
holds essentially all the weight, and the label is arbitrary there.
Post-processing relabels those as confident singlets with no secondary type, so
purification leaves them alone instead of stripping a real phenotype.

Deconvolution is not RCTD-specific. Any tool works — build an `RCTDResult`
yourself, or skip it entirely and pass `weights` + `reference` straight to
`purify()`.

## Step 3 — SPLIT

```python
purified = pysplit.purify(xenium, rctd=rctd_result, remove_residual_contamination=True)
```

Every count is rescaled by the share of expected expression attributable to the
cell's own primary cell type. `remove_residual_contamination=True` additionally
zeroes genes with no *specific* reference support in that cell type — background
that proportional redistribution cannot touch. The threshold is derived from the
reference, so there is nothing to tune.

`purified` is an `AnnData`: purified counts in `X`, aligned raw counts in
`layers['counts_raw']`, per-cell metadata in `obs`, run parameters in
`uns['pysplit']`.

Two things to know: purified counts are **fractional**, and `reject` cells are
**dropped** (they have no trustworthy annotation), so filter your raw object to
`purified.obs_names` before comparing.

## Step 4 — spatially-aware SPLIT

Purifying every cell over-corrects. A cell whose secondary signal is *not*
present in its physical surroundings more likely holds a genuine phenotype —
possibly one absent from the reference — than contamination.

```python
spatial_nw = pysplit.build_spatial_network(
    xenium, basis="spatial", k_knn=20, prune=True, radius=15,   # micrometres
)
pysplit.spatial_metrics(spatial_nw, rctd_result)
xenium.obs = xenium.obs.join(spatial_nw.to_dataframe())

spatially_aware = pysplit.balance_by_score(
    xenium, purified,
    score_name="neighborhood_weights_second_type",
    threshold=0.05,          # lower purifies more cells
)
```

`neighborhood_weights_second_type` — the **local diffusion score** — is the
share of a cell's spatial neighbourhood made up of its own secondary cell type.
High means the secondary signal really is next door, so purifying is warranted.

The `radius=15` µm pruning is what keeps the graph to physically adjacent cells;
without it the 20 nearest neighbours can reach across empty tissue and the score
stops meaning anything.

Cells above the threshold take their purified profile, the rest stay raw, and
`reject` cells are dropped. Check `obs['purification_status']` for what happened.

## Step 5 — SPLIT-shift

When contamination is strong enough, the deconvolution assigns the cell to the
*contaminating* type. SPLIT-shift swaps the labels for cells whose
transcriptomic neighbourhood agrees with neither their primary type nor its
class, while matching their secondary class — and takes the **residual** as such
a cell's profile:

```python
sc.pp.normalize_total(tmp); sc.pp.log1p(tmp); sc.pp.pca(tmp, n_comps=50)
xenium.obsm["X_pca"] = tmp.obsm["X_pca"]

transcriptomic_nw = pysplit.build_transcriptomics_network(
    xenium, basis="X_pca", dims=range(50), k_knn=100,
)
pysplit.transcriptomics_metrics(transcriptomic_nw, rctd_result)
xenium.obs = xenium.obs.join(transcriptomic_nw.to_dataframe())

shifted = pysplit.balance_by_score(
    xenium, purified, threshold=0.05,
    score_name="neighborhood_weights_second_type",
    swap_labels=True,
)
```

`k_knn=100` is deliberately large — the question is what phenotype a broad
expression neighbourhood agrees on, which needs a stable majority. Pre-swap
values survive in `*_before_swap` columns, and `obs['swap']` flags the cells.

The three modes are **combinable**: this call is spatially-aware SPLIT *plus*
label swapping.

## Step 6 — did it work?

Marker-gene specificity, scored on genes SPLIT never sees: for each cell, what
share of its counts fall on its own lineage's markers versus **foreign**
lineages? Foreign-marker signal in a cell is what contamination looks like.

```python
own, foreign = marker_specificity(adata, "first_type")
```

The script prints a table across all four variants and writes
`marker_specificity.csv`. Here is what the cropped region actually produces
(7,725 cells after RCTD's filters and SPLIT dropping `reject` cells):

| variant | own-lineage markers | foreign-lineage markers | own/foreign |
|---|---|---|---|
| Raw | 0.1518 | 0.0973 | 1.56 |
| **SPLIT** | **0.1879** | **0.0685** | **2.74** |
| Spatially-aware SPLIT | 0.1728 | 0.0791 | 2.18 |
| SPLIT-shift | 0.1765 | 0.0788 | 2.24 |

Full SPLIT raises own-lineage marker share by 24% and cuts foreign-lineage
share by 30%, improving specificity by 76%. It keeps 68% of counts.

Spatially-aware SPLIT lands *between* raw and full SPLIT — as it should: it
purified only 4,254 of 7,725 cells (55%) and left the rest untouched. A lower
`threshold` moves it towards full SPLIT. Which you want is a judgement call:
full SPLIT maximises specificity, spatially-aware SPLIT protects phenotypes
that the reference may not contain. **Higher marker specificity is not
automatically better** — a run that purified everything to nothing would score
perfectly.

There is a second, subtler caveat: the metric is **not fully independent of the
method**. SPLIT uses the reference, and that same reference encodes which genes
are lineage markers, so the score and the correction draw on overlapping
information. It is a consistency check, not a validation. For an independent
one, `examples/simulate_and_validate.py` scores the same pipeline against known
ground truth on simulated spillover (marker purity 0.75 → 0.91, with
uncontaminated cells left untouched at 0.911 → 0.911). Treat a UMAP that looks
tidier after purification the same way — SPLIT pulls each profile towards its
assigned reference, so tighter clusters are partly guaranteed by construction.

Other numbers from the same run, for calibration:

* spot classes: 81.1% `singlet`, 15.8% `doublet_certain`, 2.2%
  `doublet_uncertain`, 1.0% `reject`
* residual contamination removal chose `belonging_threshold = 0.0514`
  automatically and stripped 2.7–6.6% of each cell type's reference profile —
  in line with the 2–5% the paper reports
* the 15 µm pruning removed 80% of the 20-NN edges, which is the point: it
  keeps only physically adjacent cells
* 15% of cells disagree with their transcriptomic neighbourhood, and
  SPLIT-shift relabelled 487 of them

The notebook additionally plots the UMAP for **all four variants** as a
variants x classes grid, plus a silhouette/ARI bar chart that measures class
separation rather than leaving you to eyeball 28 panels. Read that chart with
the caveat above in mind: full SPLIT scores highest because it is the most
aggressive, not because it is necessarily the most faithful.

Also worth inspecting:

```python
xenium.obs.groupby("spot_class", observed=True)["neighborhood_weights_second_type"].median()
```

On this sample it gives `doublet_uncertain` 0.117 > `doublet_certain` 0.085 >
`singlet` 0.080. The ordering is the expected one — cells the deconvolution was
least sure about sit in the most mixed neighbourhoods — but note how *small* the
gap between `singlet` and `doublet_certain` is. The score is a property of a
cell's surroundings, not of its own annotation confidence, so do not expect it
to separate spot classes cleanly; a confident singlet in the middle of a tumour
still has a high diffusion score, which is exactly the case spatially-aware
SPLIT exists to catch.

## Optional — reassign removed transcripts

Removed counts physically belong to *some* nearby cell. Instead of discarding
them, redistribute them to the neighbours they most plausibly came from:

```python
corrected = pysplit.reassign_residual_counts(
    raw_counts=xenium[purified.obs_names, purified.var_names].X,
    purified_counts=purified.X,
    neighborhood=spatial_nw,
    purification_status=purified.obs["purification_status"],
    cell_names=list(purified.obs_names),
    mode="count_proportional",
)
```

## Optional — the pie plot

```python
pie_df = pysplit.pie_dataframe(rctd_result)
cell = xenium.obs.query(
    "neighborhood_weights_second_type > 0.2 and first_type == 'CD4+_T_Cells'"
).index[0]
pysplit.plot_pie_around_cell(pie_df, cell_id=cell, radius=50)
```

Slice areas are the primary/secondary weights, the pie edge marks the primary
cell type, and the centre marker encodes the spot class (coloured dot =
`doublet_certain`, black dot = `doublet_uncertain`, cross = `reject`, nothing =
confident `singlet`). A T cell sitting inside a tumour region shows up
unmistakably as a pie half-filled with the tumour colour.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `CERTIFICATE_VERIFY_FAILED` from `rctd-py` | Q-matrix auto-download; fetch it with `curl` (Step 2) |
| RCTD appears to hang with no output on CPU | `torch.compile`; pass `compile=False` (Step 2) |
| `class_df is missing entries for cell types: [...]` listing every type | `rctd-py` needs a dict, not a DataFrame (Step 1) |
| `has not been post-processed by SPLIT` | run `pysplit.run_post_process_rctd(rctd)` first |
| `Reference and deconvolution cell types do not match` | reference and weights disagree on labels; check for renamed or dropped types |
| Purified object has fewer cells | `reject` cells are dropped by design |
| Everything purified, nothing kept raw | threshold too low, or spatial metrics missing from `obs` |
| `*_class` metrics missing | pass `class_df` to your `RCTDResult` |
| Non-integer counts break a downstream tool | expected; round if that tool insists |
